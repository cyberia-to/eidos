## Delivered scope

Strict admission-free checking and correct Pi-universe behavior; kernel-checked
binary positive/nonnegative arithmetic; concrete quotient/remainder certificate
checking, including rejection controls. These changes support Hemera's explicit
algebraic proofs and per-input arithmetic certificates.

The current trusted base includes Rust execution and the fixed inductive
bootstrap. General inductive validation, bounded normalization and universal
machine-word refinement remain open. The public certificate prototype uses
FNV-1a; nox execution, zheng certificates and cybergraph search are unimplemented.
`search` and `verify` remain CLI stubs. The README now states these boundaries.

## Publication boundary

A research source snapshot can preserve this tested work with the limitations
above. A polished installable `v0.1.0` remains subject to the existing
[release roadmap](../roadmap/README.md): standalone fixtures, honest CLI surface,
package metadata/licensing material and packaging verification.
No kernel soundness, cryptographic security or production certification follows
from these functional tests.

The source validation bundle includes the pinned `nox/proofs` and `prysm/proofs`
trees. It preserves nox's committed `rs/LICENSE` as license context; prysm's
manifest declares `Cyber` without a standalone license file. Eidos manifests
declare `MIT` without a standalone LICENSE file at this snapshot. The bundle
records these declarations and does not substitute a new license grant.
